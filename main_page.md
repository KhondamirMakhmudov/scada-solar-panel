# Overview Stations API

2026-09-22 · @Someone

`GET /api/v1/overview/stations` отдаёт одним запросом состояние всех станций, каждого инвертора и суммарную выработку — для дашборда, где сразу видно, что работает, что сломалось и когда работало в последний раз.

## Запрос

`GET /api/v1/overview/stations` на scada\_storage, в проде `http://10.20.6.23:8102`. Параметров нет, ответ всегда полный.

|  |  |
| --- | --- |
| Метод | `GET` |
| Путь | `/api/v1/overview/stations` |
| Авторизация | `Authorization: Bearer <access token>` |
| Право | `scada_storage:read` |
| Ответ | `200 application/json` |

Токен нужен обычный пользовательский, тот же, что для `/api/v1/tag-values`. Сервисные токены этот сервис не принимает: проверяется `type == "access"`, дальше право по ролям пользователя.

Ответ собирается из одного запроса в базу плюс опрос поллеров станций с кешем 10 секунд, поэтому дёргать раз в 10–30 секунд нормально. Чаще смысла нет: значения приходят с опросом раз в 30 секунд, а блок поллеров всё равно отдаётся из кеша.

## Структура ответа

Четыре уровня вложенности: ответ → станция → соединение (PLC или шлюз) → устройство (инвертор). Все поля в camelCase.

### Корень

| Поле | Тип | Что внутри |
| --- | --- | --- |
| `generatedAt` | ISO 8601, UTC | Момент сборки ответа |
| `totals` | объект | Итоги по всем станциям |
| `stations` | массив | По одному элементу на `driverId` |

`totals` содержит `stations`, `devices`, `deviceCounts` и `energy` — те же поля, что у станции, но суммарно.

### Станция

| Поле | Тип | Что внутри |
| --- | --- | --- |
| `driverId` | строка | Идентификатор станции: `tashkent_ttc`, `sirdarya_tpp`, `mubarek_tpp`, `fergana_tpc`, `tpp` |
| `status` | строка | `online`, `degraded`, `offline`, `disabled`, `unknown` |
| `deviceCounts` | объект | Сколько устройств в каждом статусе, например `{"online": 13, "offline": 17}` |
| `lastSeen` | ISO 8601 или `null` | Самое свежее значение по станции |
| `energy` | объект | `currentPowerW`, `todayKwh`, `totalKwh` |
| `pollerReachable` | `true`/`false`/`null` | Ответил ли поллер станции; `null` — адрес не настроен |
| `pollerError` | строка или `null` | Причина недоступности поллера |
| `connections` | массив | Соединения станции |

### Соединение

| Поле | Тип | Что внутри |
| --- | --- | --- |
| `id`, `name` | строка | UUID и имя, например `fergana_tpc_plc_2_abk` |
| `type` | строка | `MODBUS_TCP`, `MODBUS_RTU_OVER_TCP`, `OPC_UA` |
| `enabled` | булево | Включено ли в конфиге |
| `status` | строка | Свёртка по своим устройствам |
| `poller` | объект или `null` | Срез воркера этого соединения |
| `devices` | массив | Инверторы |

### Устройство

| Поле | Тип | Что внутри |
| --- | --- | --- |
| `id`, `name` | строка | UUID и имя, например `fer_tpc_inv_17` |
| `status` | строка | `online`, `idle`, `error`, `offline`, `unknown`, `disabled` |
| `lastSeen` | ISO 8601 или `null` | Когда пришло последнее значение |
| `staleSeconds` | число или `null` | Сколько секунд назад это было |
| `errorMessage` | строка или `null` | Текст ошибки чтения с устройства |
| `statusLabel` | строка или `null` | Расшифровка тега `status`: `Normal`, `Waiting`, `Fault` |
| `energy` | объект | `currentPowerW`, `todayKwh`, `totalKwh` |

`statusLabel` берётся из `value_map` тега в конфиге и зависит от модели инвертора: у Growatt `1` это `Normal`, у Solax `3` — `Online`. Где `value_map` не задан, придёт `null`. Рендерить стоит `statusLabel`, а не сырое число.

## Статусы

Статус устройства считается на сервере из последних значений его тегов. На фронте ничего досчитывать не надо.

| Статус | Когда | Как показывать |
| --- | --- | --- |
| `online` | Свежие данные, ошибок нет | Зелёный |
| `idle` | Свежие данные, `currentPowerW = 0`, статус не рабочий | Серый, не красный — это ночь или остановленный инвертор |
| `error` | Последнее чтение с ошибкой | Жёлтый, текст из `errorMessage` |
| `offline` | Молчит дольше порога | Красный, рядом `lastSeen` |
| `unknown` | Значений не было никогда | Красный или прочерк |
| `disabled` | Выключен в конфиге | Бледный, в аварии не считать |

Порог молчания — `max(3 × scanRate, 2 минуты)`. При текущем опросе раз в 30 секунд это 2 минуты.

Разделение `idle` и `offline` принципиальное: ночью солнечные инверторы гаснут и отдают нулевую мощность, при этом продолжая отвечать. Если красить их аварийным цветом, каждый вечер дашборд будет целиком красным.

### Свёртка до соединения и станции

У соединения и станции свой набор значений, не такой же, как у устройства:

- `online` — все устройства в `online` или `idle`
- `offline` — все в `offline` или `unknown`
- `degraded` — любое смешанное состояние, включая хоть один `error`
- `disabled` — все устройства выключены
- `unknown` — устройств нет вовсе

Значения `degraded` у устройства не бывает, а `idle` и `error` не бывает у станции. Если нужна детализация по станции — смотри `deviceCounts`, там разбивка по всем шести статусам.

## Выработка и поллеры

Блок `energy` одинаковый на всех трёх уровнях — устройство, станция, итого.

| Поле | Единицы | Значение |
| --- | --- | --- |
| `currentPowerW` | ватты | Мгновенная мощность |
| `todayKwh` | кВт·ч | Выработка за сегодня |
| `totalKwh` | кВт·ч | Счётчик нарастающим итогом за всё время |

Сумма станции — это сумма **последних известных** значений по всем её инверторам, включая те, что сейчас `offline`. Сделано так намеренно: `totalKwh` — счётчик, и если выкидывать молчащие инверторы, общая выработка станции будет проваливаться при каждом обрыве связи. Поэтому рядом с цифрой стоит показывать `deviceCounts`: если там есть `offline`, цифра частично устаревшая.

У устройства без данных все три поля равны нулю, а не `null` — суммировать можно без проверок.

### Блок поллеров

Поля `pollerReachable` и `poller` отвечают на вопрос, почему данных нет. Они берутся из `/health` службы опроса на самой станции.

В `connections[].poller` лежит срез воркера именно этого соединения: `connected`, `circuit_breaker` (`CLOSED`, `HALF_OPEN`, `OPEN`), `failures`, `last_success_age_seconds`, `tags`. Поле равно `null`, если поллер не ответил.

Различать три случая:

| Что видно | Что случилось |
| --- | --- |
| `pollerReachable: false` | Сервер станции недоступен или служба лежит, причина в `pollerError` |
| `poller.circuit_breaker: OPEN` | Служба жива, но PLC не отвечает — сеть или железо на месте |
| `poller.connected: true` при `offline` устройствах | PLC отвечает, молчит сам инвертор |

Поллеры опрашиваются параллельно с таймаутом 3 секунды, ответ кешируется на 10 секунд. Недоступный поллер не ломает ответ: остальные станции придут как обычно.

## Что учесть

Состояние контура на 22 сентября 2026 — полезно для проверки вёрстки на реальных данных:

| Станция | Инверторов | Состояние |
| --- | --- | --- |
| `tashkent_ttc` | 8 | Все отвечают |
| `sirdarya_tpp` | 16 | 15 отвечают, один остановлен физически |
| `fergana_tpc` | 30 | 13 отвечают; 3 PLC недоступны по сети, 12 слейвов не отвечают на шине |
| `mubarek_tpp` | 10 | PLC недоступен, данных нет вообще |
| `tpp` | 3 | Все отвечают |

Значит, вёрстка должна нормально выглядеть при станции целиком без данных: `lastSeen: null`, нулевая выработка, все устройства в `unknown`.

Остальное:

- Ночью почти всё уйдёт в `idle` с нулевой мощностью — это норма, не авария.
- OPC-UA станции (`sirdarya_tpp`, `mubarek_tpp`, часть `fergana_tpc`) работают по подписке и шлют только изменения. У застывшего значения `staleSeconds` растёт до 5 минут, пока не сработает heartbeat. Порог `offline` это учитывает.
- `deviceCounts` содержит только ненулевые ключи: если аварий нет, ключа `error` в объекте просто не будет.
- Истории работоспособности ручка не отдаёт — только текущий срез и `lastSeen`. Графики за период стройте через `/api/v1/tag-values/aggregates`, как и раньше.
- Новая станция появляется в ответе сама, как только её заводят в конфиге. Список `driverId` в коде фронта зашивать не надо.
