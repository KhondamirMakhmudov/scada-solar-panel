# Аналитика SCADA: руководство для фронта

Сервис `scada_analytics` отвечает на вопросы руководства и диспетчеров («сколько выработали, от какой мощности,
кто не работает»). Он не хранит данные: состав (станции, устройства, роли тегов) берёт из `scada_config`,
показания — из часовых агрегатов `scada_storage`, и считает отчёт на каждый запрос.

Фронт получает готовые цифры и сам рисует график, таблицу и собирает Excel.

## Подключение

- Адрес: `http://10.20.6.23:8105`, Swagger: `/docs`.
- Авторизация как у остальных сервисов: `Authorization: Bearer <accessToken>` (тот же токен из next-auth).
  Пользователю нужны права чтения `scada_config` и `scada_storage`.
- Все поля ответа — camelCase. Время — ISO 8601 с зоной `+05:00` (Ташкент), даты — местные.
- Ошибки в общем формате `{"message": "...", "details": ...}`:

| Код | Когда | Что показать |
|---|---|---|
| 401 | нет токена / истёк | обновить токен, повторить |
| 403 | нет прав на config/storage | «Нет доступа к аналитике» |
| 404 | неизвестный id в `siteIds`/`deviceIds` | сбросить выбор, перечитать справочник |
| 422 | неверные параметры (`details`: поле и текст) | ошибка формы |
| 502 | config или storage недоступны | «Данные временно недоступны», повтор |

## Шаг 1. Справочники для выбора

Выбор «все / несколько станций / одна станция / отдельные инверторы» строится из двух запросов к `scada_config`
(их можно кешировать на время сессии):

**Станции** — `GET http://10.20.6.23:8100/api/v1/sites` → `data[]`:

```json
{
  "id": "c0db1f45-…",
  "code": "navoi",
  "name": "\"Навоий ИЭС\" акциядорлик жамияти",
  "groupName": "\"Smart Integrity МЕ\" МЧЖ",
  "type": "solar",
  "installedPowerKw": 1258.0,
  "passport": { "order": 1, "modulesCount": …, "invertersCount": …, "inverterPowerKw": …, "landAreaM2": …, … }
}
```

Сортировать по `passport.order` (официальный порядок отчёта). `groupName` — для группировки в списке.

**Инверторы** — `GET http://10.20.6.23:8100/api/v1/driver-configs` → `data[].devices[]`:

```json
{ "id": "b3d3caa8-…", "name": "fer_tpc_inv_1", "siteId": "b2b64af0-…", "ratedPowerKw": null, "enabled": true }
```

Дерево выбора: станция → её инверторы (`device.siteId == site.id`). Станции без инверторов показывать
неактивными («не подключена к SCADA»).

## Шаг 2. Запрос отчёта

```
GET /api/v1/solar/production/day?date=2026-09-24&siteIds=<id>,<id>&deviceIds=<id>&breakdown=site
```

| Параметр | Что это |
|---|---|
| `date` | Местная дата `YYYY-MM-DD`. Без неё — сегодня |
| `siteIds` | Станции целиком, через запятую. Мощность — из паспорта станции |
| `deviceIds` | Отдельные инверторы. Мощность — номинал инвертора. Можно вместе с `siteIds` |
| `breakdown` | `none` (по умолчанию), `site` — те же 24 часа по станциям, `device` — по инверторам |

Ничего не выбрано → все солнечные станции, у которых есть устройства.

Для сегодняшнего дня данные живые (текущий час тоже), обновлять страницу раз в 5 минут достаточно.
Запрос считается за 1–3 с — показывать загрузку.

## Шаг 3. Ответ

Реальный ответ с прода (сокращён):

```json
{
  "date": "2026-09-24",
  "timezone": "Asia/Tashkent",
  "capacityKw": 6941.7,
  "capacityMissingFor": [],
  "summary": {
    "energyKwh": 5591.09,
    "yesterdayEnergyKwh": 10312.25,
    "yesterdaySameTimeKwh": 10312.25,
    "deltaPercent": -45.8,
    "peakHour": { "start": "2026-09-24T13:00:00+05:00", "energyKwh": 1033.56, "percentOfCapacity": 14.9, "devicesReporting": 40 }
  },
  "hours": [
    { "start": "2026-09-24T12:00:00+05:00", "energyKwh": 979.23, "percentOfCapacity": 14.1, "devicesReporting": 40 }
  ],
  "breakdown": [
    { "id": "2cdbdde0-…", "name": "\"Сирдарё ИЭС\" филиали", "kind": "site", "siteName": null,
      "capacityKw": 1924.1, "energyKwh": 3337.2, "hours": [ … 24 элемента … ] }
  ],
  "coverage": {
    "devicesSelected": 67,
    "devicesWithData": 40,
    "silent": [
      { "deviceId": "b3d3caa8-…", "deviceName": "fer_tpc_inv_1", "siteName": "\"Фарғона ИЭМ\" филиали",
        "lastSeen": null, "reason": "no_readings_today" }
    ]
  },
  "anomalies": [
    { "deviceId": "60929ddd-…", "deviceName": "fer_tpc_inv_14", "hourStart": "2026-09-24T07:00:00+05:00", "kind": "spike" }
  ]
}
```

### Поля

| Поле | Значение |
|---|---|
| `capacityKw` | Уровень 100%: сумма паспортной мощности выбранных станций + номинал выбранных инверторов. `null`, если у кого-то мощность неизвестна |
| `capacityMissingFor[]` | Имена станций/инверторов без мощности. Если не пусто — `capacityKw` и все `percentOfCapacity` = `null` |
| `hours[]` | Всегда 24 элемента, по местным часам 00:00…23:00 |
| `hours[].energyKwh` | Выработка за час, кВт·ч (= средняя мощность за час в кВт). `null` — неизвестно или час не наступил |
| `hours[].percentOfCapacity` | `energyKwh / capacityKw × 100` |
| `hours[].devicesReporting` | Сколько устройств прислали показания в этот час |
| `summary.energyKwh` | За сутки (для сегодня — на текущий момент) |
| `summary.peakHour` | Час с максимальной выработкой (тот же формат, что `hours[]`), `null` если данных нет |
| `summary.yesterdayEnergyKwh` | Вчера за весь день |
| `summary.yesterdaySameTimeKwh` | Вчера за те же завершённые часы, что прошли сегодня |
| `summary.deltaPercent` | Сегодня к вчера за те же часы, % (`null`, если вчера 0/нет данных) |
| `breakdown[]` | Пусто при `breakdown=none`. Иначе по станции/инвертору: `id`, `name`, `kind` (`site`/`device`), `siteName` (у инвертора — его станция), `capacityKw`, `energyKwh`, свои `hours[]` |
| `coverage.devicesSelected` / `devicesWithData` | «данные от 40 из 67 устройств» |
| `coverage.silent[]` | Кто молчит: `reason` = `no_readings_today` (нет показаний сегодня, `lastSeen` — последнее за 2 суток или `null`) или `no_energy_counter` (у инвертора нет тега с ролью `energy_today`, считать нечем) |
| `anomalies[]` | Часы инвертора, отброшенные как сбой счётчика (`kind: "spike"` — больше 1.5 × номинала) |

## Шаг 4. Как рисовать страницу

```
┌───────────────────────────────────────────────────────────────┐
│ [дата ◀ ▶]  [выбор: все / станции / инверторы]  [по станциям ▾] [Excel] │
├───────────────────────────────────────────────────────────────┤
│ За сутки 5 591 кВт·ч   ▼ 45.8% к вчера   Пик 13:00 — 1 034 кВт·ч (14.9%) │
│ ⚠ Данные от 40 из 67 устройств  [кто молчит]                      │
├───────────────────────────────────────────────────────────────┤
│ 6942 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  (установл. мощность)   │
│                    ▆ ▇ █ ▇ ▆                                      │
│              ▂ ▄ ▅ █ █ █ █ █ ▅ ▃ ▁           ░ ░ ░ (ещё не наступило) │
│ 00  03  06  09  12  15  18  21                                    │
├───────────────────────────────────────────────────────────────┤
│ Таблица: строка на станцию/инвертор × 24 часа + итог + %          │
└───────────────────────────────────────────────────────────────┘
```

- **Столбики**: `hours[].energyKwh`, подпись — кВт·ч и `percentOfCapacity`%.
  При `breakdown=site|device` — стековые столбики из `breakdown[].hours`.
- **Черта мощности**: горизонтальная линия на `capacityKw`. Если `null` — не рисовать, вывести
  «нет номинала у: …» из `capacityMissingFor`, график оставить в кВт·ч.
- **Черта пика**: по `summary.peakHour`, подпись «Пик 13:00 — 1 034 кВт·ч».
- **`energyKwh: null` — не ноль.** Рисовать пустым/серым. Для сегодняшних будущих часов — «ещё не наступило».
- **Неполный час**: днём (примерно 07–19) `devicesReporting` < `coverage.devicesSelected` — часть устройств
  не прислала данные в этот час, цифра может быть занижена. Значок ⚠ на столбике с подсказкой
  «данные от N из M».
- **Сравнение**: `deltaPercent` зелёным ▲ / красным ▼, подсказка «вчера за то же время:
  `yesterdaySameTimeKwh`, за весь день: `yesterdayEnergyKwh`».
- **Кто молчит**: список `coverage.silent[]` по станциям, «последние данные: `lastSeen`» или «нет данных 2+ суток».
- **Аномалии**: значок на часе `anomalies[].hourStart` с подсказкой «отброшен сбой счётчика: `deviceName`».

## Шаг 5. Excel (собирает фронт)

Запросить с `breakdown=site` (или `device` для одной станции), затем:

| Станция | Мощность, кВт | 00:00 | … | 23:00 | Итого, кВт·ч | Пик, % |
|---|---|---|---|---|---|---|
| `breakdown[].name` | `capacityKw` | `hours[0].energyKwh` | … | `hours[23].energyKwh` | `energyKwh` | max `percentOfCapacity` |
| **Итого** | `capacityKw` | `hours[0].energyKwh` | … | `hours[23].energyKwh` | `summary.energyKwh` | `summary.peakHour.percentOfCapacity` |

`null` писать пустой ячейкой, не 0. Строки станций уже идут в официальном порядке паспорта.
Внизу можно добавить «Данные от N из M устройств» и список молчащих.

## Как считается (для понимания цифр)

- Выработка часа = прирост **суточного** счётчика инвертора (тег с ролью `energy_today`) за час.
  Сброс счётчика (ночью/утром) распознаётся, после сброса значение само является выработкой.
- Счётчик за всё время не используется: на Фергане (OPC) и Сырдарье он скачет и уменьшается.
- Час больше 1.5 × номинала (или 1.5 × максимальной мощности, которую инвертор показывал) — сбой, отбрасывается
  и попадает в `anomalies`.
- В расчёт идут только показания с качеством `good`; сомнительные и ошибочные в отчёт не попадают.
- Если в часе показаний нет, берётся последнее известное значение счётчика — отсюда `devicesReporting`.
